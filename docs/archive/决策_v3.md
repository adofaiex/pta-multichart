## 1. 按来源分开的事实

### 1.1 仓库事实

**P1 仍是硬事实。** `结果_v1.md` §3 记录了 r150 的 `scrFloor.entryTime`：BPM 100 下 `[180,180]` 的下一次主轨点击在 2.400s；切成 `[180,270,180]` 后插入点在 2.100s，下一次主轨点击在 3.000s，晚 1 拍，不是 0.5 拍。`Timing.cs` 的行程是 `sweep / π`，每多一块砖多一段 π。`ChartCompiler` 没有把这 1 拍扣回去。本环境没有游戏，也没有 `dotnet`，没有重跑那 5 张谱。P1 的地位来自已入库的实测记录，加上与它一致的已入库模型。

**P2 的写入只有 A2。** `EmitPositionCorrections`：

- `need = idealPos[i] − natural[i]`
- `own = need − carry`
- 插入砖：一条 `PositionTrack`，`opacity = 0`，`justThisTile = true`，`positionOffset = own`，carry 不变
- 非插入砖：`own` 非零才写一条不带 `opacity`、不带 `justThisTile` 的 `PositionTrack`，然后 `carry = need`

`positionOffset` 的两处赋值都是 `own`（208 行、216 行）。全仓库没有第二处 PositionTrack 偏移写入（装饰的 `MoveDecorations` 是另一类事件）。

`notes-compile.md` 第 21 行和第 27 行把单处切分写成 `ideal − natural` 和 `v(angleData[k]) − Σ v(exit_i)`。同文件第 32 行写「按相对 carry 的增量发事件」。单处切分时 carry 从 0 开始，两种写法数值相同。`tests/CompileTests` 的 `TestBasicInsert` 锁定的就是这一例：插入砖 `(-0.5, 0.5)`，后继砖 `(0, 1)`。`TestRepeatConstant` 对三处切分做的是形状断言：模拟引擎 carry 之后，每块逻辑砖回到原位置。它没有把第二处切分的原始 `positionOffset` 写成断言。

**第二轮代码不在这次提交里。** 没有预检类型，没有「保留作者 tag、交集字符串不写入」的分支，CompileTests 源码长度与摘录所记的第一轮 658 行相同。`结果_v1.md` §5.2 仍是仓库里唯一的 5 张谱判定表。

### 1.3 按已提交源码重算的一表

这不是新的游戏实测，也没有写入仓库。它只用 `79b1418` 里的函数，核对附件探针是不是这条函数的推论。

`(0,0) (-1,0) (-1,-1) (-2,-1) (-2,-2) (-3,-2)`

第二处插入砖的理想点在弦 `(-2,0)→(-3,0)` 的弧中点 `(-2.5,-0.5)`。此时上一处后继砖已经把 carry 设为 `(0,1)`。

| 播放砖 | 事件 | `need = ideal − natural`（A1 会写入的数） | 编译器写入的 `own = need − carry`（A2） |
| --- | --- | --- | --- |
| 2 | PT-1，`justThisTile` | `(-0.5, 0.5)` | `(-0.5, 0.5)` |
| 3 | PT-2，向后传递，随后 carry 变为 `(0,1)` | `(0, 1)` | `(0, 1)` |
| 4 | PT-1，`justThisTile` | `(-0.5, 1.5)` | `(-0.5, 0.5)` |
| 5 | PT-2 | `(0, 2)` | `(0, 1)` |

附件摘录里的四个数就是这一表。A1 与 A2 从第二处切分开始分开；编译器写下的是右列。若把右列改成左列，引擎 carry 会把第二处插入砖再抬 `(0,1)`，落到 `(-2.5, 0.5)`，离开弧中点 `(-2.5,-0.5)`。`TestRepeatConstant` 的形状断言拒绝这种改法。

## 4. 什么条件下才再开

再开时另写决策。下面任一情况成立，并且依据能在仓库里指出路径，才开。只在附件里出现，不算。

1. **有人即将修改已经写出的 PositionTrack 数值，或另写一套补偿。** 先用仓库里的 `ChartCompiler` 对现有谱算出偏移表，表上要有一处 A1 与 A2 数值不同的切分。命中现行 `own = need − carry` 就把这句写进当时已经在仓库里的方案；两套都不等于编译器输出，就停，不发明第三套式子。游戏只在「该数不在编译器输出里、只在桥的抓取里」时使用：隐藏桌面，`pta-bridge` HTTP `127.0.0.1:59731`。禁止 computer use。
2. **非最后一块砖的 `entryBeat` 在引擎里为 0，或仓库里那 5 张谱的判定偏离 `结果_v1.md` §5.2。** 回归基准是结果 v1 那一表（t1 三次 XPerfect，t2 七次，t3 五次，t6 五次，t4 四次 XPerfect 加一条 Midspin 自动记录，死亡都是 0）。`结果_v2.md` 未入库，不能当基准。
3. **下一次改动必须让导出的 `entryBeat` 等于 C# 累计值。** 那时才处理分歧 D。在此之前保持引擎口径，不把模型累计值写回引擎。

下列情况不构成再开：

- 只是想把 `notes-compile.md` 第 21 行和 `EmitPositionCorrections` 收成同一句话。写方案的人抄 199–218 行即可。
- 附件里的 `方案_v2.md` / `结果_v2.md` / 摘录还停在某台机器上，尚未进入 `main`。那是入库问题。入库本身不授权改拍、改偏移或重跑第三轮。
- 结果 §7 里除上述三条以外的未做项。
