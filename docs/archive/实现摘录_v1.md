## 1. 两条 PositionTrack（P2）

### 1.0 引擎侧机制（决定这两条事件怎么写的唯一依据）

`scnGame.ApplyCoreEventsToFloors` 里的原始行：

```csharp
scnGame.cs:335   Vector2 vector2 = Vector2.zero;            // 累加器，初始 0
scnGame.cs:380   item5.TryGet<bool>("justThisTile", out var output6);
scnGame.cs:515   if (!item5.disabled["positionOffset"])     // key 缺省 = disabled = 不生效
scnGame.cs:522       vector2 += item5.Get<Vector2>("positionOffset") * ADOBase.controller.tileSize;
scnGame.cs:529-532  if (!output6) { vector = vector2; }     // 只有非 justThisTile 才把累计值传给后面
scnGame.cs:639   floor4.transform.position = floor4.startPos + new Vector3(vector2.x, vector2.y, 0f) + ...
scnGame.cs:640   floor4.offsetPos = new Vector3(vector2.x, vector2.y, 0f) + ...
scnGame.cs:641   vector2 = vector;
```

复述：**本砖最终位置 = 起点位置 + （上砖传下来的 `vector` + 本砖所有 `positionOffset`×tileSize）**；
本砖只要出现一条**非** `justThisTile` 的 `PositionTrack`，这个累计值才成为后续砖的 `vector`；
否则变更只作用于本砖，不回传。同一条砖上多条 `PositionTrack` 是**加法叠加**。
（编译层自己复刻这套规则的实现：`tests/CompileTests/Program.cs:132-158` 的 `SimulatePositions`。）

`IdealArcPoint` 原文（`ChartCompiler.cs:226-243`）：

```csharp
Vec2 chord = end - start;
double sinHalf = Math.Sin(sweep * 0.5);
if (sinHalf < 1e-6) return start + chord * f;                  // 回头弯/极小角：直线兜底
double radius = 0.5 / sinHalf;
Vec2 mid = (start + end) * 0.5;
Vec2 leftPerp = new Vec2(-chord.Y, chord.X);                   // 弦方向的左手法线
double s = isCCW ? 1.0 : -1.0;
Vec2 center = mid + leftPerp * (s * radius * Math.Cos(sweep * 0.5));
Vec2 r0 = start - center;
return center + Rotate(r0, s * sweep * f);
```

`sweep = π` 时退化成「圆心 = 弦中点、半径 0.5、起点半径向量 = `start − 中点`、按 `s·sweep·f` 旋转」。

## 2. ★ 读法分歧（T2 停止条件）

### 2.1 分歧 A（**必须你定**）：偏移量的基准是「绝对」还是「相对 carry 的增量」

两种读法都能从代码里读出来：

- **读法 A1（绝对）**：「`positionOffset` = `ideal − natural`」。
  支持：`ChartCompiler.cs:199` 先算 `need = idealPos[i] − natural[i]`；
  `notes-compile.md:21`、`:27` 就是这么写的（`ideal − natural`、`v(angleData[k]) − Σ v(exit_i)`）；
  单处切分时与代码写进 `Data` 的数完全一致（§1.4 第一例）。
- **读法 A2（增量）**：「`positionOffset` = `ideal − natural − carry`」，`carry` = 前面已传递下来的累计偏移。
  支持：`ChartCompiler.cs:200`（`own = need − carry`）与 `:208`/`:216` 写进 `Data` 的正是 `own`；
  `:218` 只在发出 PT-2 时更新 `carry`。

两者何时给出不同数值：**同一张谱里出现第二处及以后的切分**（第一处 `carry == 0`，两种读法相同）。
§1.4 第二例：第二处切分的 PT-1 写 `(-0.5, 0.5)`，而 `ideal − natural` 是 `(-0.5, 1.5)`；
PT-2 写 `(0, 1)`，而 `ideal − natural` 是 `(0, 2)`。

后果：若 v2 只写 A1，照它重写的人会在多处切分的谱上把误差累加成两倍、位置会再次错开一块；
若 v2 写 A2，则必须同时定义 `carry` 的更新时机（只在非插入砖的补偿事件上更新，插入砖不更新）。
**两种读法我都没有替你选。**

### 2.2 分歧 B：PT-2 的「参考砖」两种说法（已核：数值等价）

- **说法 B1（意图）**：「挂在被切砖 `k` 的后继砖，即逻辑 `k+1` 对应的播放砖 `ToPlayable(k+1)`」。
  来源：`notes-compile.md:27`、Lead 派单原文、`决策_v1.md` §P2 的措辞。
- **说法 B2（代码字面）**：「任何一块 `need ≠ carry` 且不是插入砖的播放砖」。来源 `ChartCompiler.cs:213-218`。

为什么两者在所有输入上等价（供你判断要不要在 v2 里分两句写）：对**未切分**的逻辑砖，
`ideal` 与 `natural` 都以 `v(angleData[i])` 推进（`ChartCompiler.cs:74` 与 `:178-181`），
所以 `need` 在相邻未切砖之间恒定；只有在切分砖内部（插入砖）和切分砖之后的第一块砖处 `need` 才变。
因此代码只会命中「后继砖」这一块。这只解释了**位置**，不改变 `carry` 的口径——`carry` 仍然是 A1/A2 的分歧点。

### 2.3 单读法、但没有判定侧证据的一项：`IdealArcPoint` 的旋向

`ChartCompiler.cs:239` 只有一种读法：`s = isCCW ? +1.0 : -1.0`（逆时针取正、顺时针取负）。
这条决定了插入砖往弦的哪一侧鼓。它在第一轮**没有被判定侧证据覆盖**：5 张谱全是 XPerfect、0 死亡，
但判定只取决于角度与拍，`positionOffset` 只挪图形；所以「符号对不对」只能靠肉眼/坐标核对。
若游戏里插入砖往弧的另一侧鼓，改的就只有这一个符号（`ChartCompiler.cs:239`）。

### 2.4 分歧 D：最后一块 `entryBeat`（模型 vs 引擎）

见 §6：引擎侧恒 0，C# 模型在 `n ≥ 3` 时是累计值。`决策_v1.md` P6 把「恒 0」记为现状口径；
摘录只指出两边不一致，不选边、不改代码。

## 3. 装饰折线（P3）

### 3.1 段的两端（代码事实）

`ChartCompiler.AddPlanetMoves`（`ChartCompiler.cs:698-723`）一共只产出两种段：

| 段 | 起点（= `MoveDecorations` 挂的播放砖） | 终点（`positionOffset` 的目标） | `duration` 的秒数 | 出处 |
|---|---|---|---|---|
| 第 1 段 | **锚点砖**：`map.ToPlayable(plan.Anchor)` | 第一次插入点击的副轨砖 `world[first.SubSeq]` | `first.Time − plan.AnchorTime` | `:709-712` |
| 第 i 段（i≥1） | 第 i 次点击的**插入砖**：`a.PlayableSeq` | 下一次点击的副轨砖 `world[b.SubSeq]` | `b.Time − a.Time` | `:714-722` |

- 所以折线的节点是 **`[锚点砖] + [每次插入点击对应的副轨砖]`**；
  `决策_v1.md` P3 的措辞「以副轨相邻点击砖为段」严格说只覆盖第 2 段起，第 1 段的起点是**锚点砖**而不是点击砖
  （锚点砖本身在主轨上已经是一次点击，见 §4）。
- **最后一击之后没有段**：循环条件 `i + 1 < plan.Clicks.Count`（`:715`），所以最后一次点击到副轨终点没有运动。
- 只有 1 次点击时只产出第 1 段；`plan.Clicks.Count == 0` 直接返回（`:701`）。
- `a.PlayableSeq < 0` 的段跳过（`:719`），正常编译不会出现。
- 段的时间基是**副轨点击的歌曲时间差**（`SubClick.Time`，`ChartCompiler.cs:326-331`）；
  编译时所有插入时刻都在**插入前**的主轨时间线上算（`mainTl` 只在 `:43` 建一次，插完不回算）。

### 3.2 `duration` / 目标点 / 缓动

`AddMove`（`ChartCompiler.cs:733-745`）：

```csharp
if (seconds <= TimeEps) return;                                  // :736
double beats = seconds * mainBpm / 60.0;                         // :742  单位 = 播放谱的拍
double dx = target.X - start.X;  double dy = target.Y - start.Y; // :737-738
actions.Add(DecorationBuilder.MoveDecorations(floor, redTag,  beats, dx, dy));   // :743
actions.Add(DecorationBuilder.MoveDecorations(floor, blueTag, beats, dx, dy));   // :744
```

- `start` **固定** = `world[1]`（`:707`），即两颗星球装饰的初始位置（副轨 1 号砖 = 锚点砖），
  **不是**上一段结束时的位置。因为引擎侧是 `startPos + targetPos`（`ffxMoveDecorationsPlus.StartEffect`），
  `positionOffset` 天然是「相对装饰自身 `startPos` 的绝对量」（`ffxMoveDecorationsPlus.cs:148` 取 `dec.startPos`、`:159` 用 `startPos.x + targetPos.x`）。
- `target` = `WorldPos(world, subSeq)`（`:725-731`），即那块副轨砖的世界坐标（砖长，1 号砖 = 锚点）。
- 同一段红蓝各写一条（`:743-744`），两条的 `duration` / `positionOffset` 相同，只有 `tag` 不同。
- 字段拼装：`DecorationBuilder.cs:146-154`（`duration` / `positionOffset` / `ease = "Linear"` / `tag`）。
- 起点段若 `target == start` 或 `seconds <= 0`，这一段不写事件（`:736`、`:739`）。

## 6. 最后一块 `entryBeat` = 0 的位置（P6）

### 6.1 引擎侧（这就是「恒为 0」的来源）

```csharp
scrLevelMaker.cs:659   scrFloor2.entryBeat = -1.0;                          // 0 号砖
scrLevelMaker.cs:660   double num7 = 0.0;
scrLevelMaker.cs:661   for (int j = 1; j < listFloors.Count - 1; j++)      // 只到 Count-2
scrLevelMaker.cs:664       scrFloor5.entryBeat = num7;
scrLevelMaker.cs:666       num7 += num8 / Math.PI + (double)scrFloor5.extraBeats;
```

最后一块砖（`j == Count-1`）**不在循环里**，所以它的 `entryBeat` 保持 `scrFloor.ResetFloor` 里的默认值：

```csharp
scrFloor.cs:541   entryBeat = 0.0;
```

结论：**「最后一块 entryBeat 恒为 0」是引擎的初始化默认值，不是算出来的**。
它的可观察后果在 `scnGame.cs:1060`（`RepeatEvents` 的旋转 offset 用 `(target.entryBeat − host.entryBeat) * 180`）。

### 6.2 C# 模型侧（`src/Core/Timing`）

```csharp
Timing.cs:270-274   if (i == 0)      { f.EntryBeat = -1; f.EntryTime = 0; }
Timing.cs:275-281   else if (i == 1) { f.EntryBeat = 0; f.EntryTime = 0; beat = 0; time = 0; }
Timing.cs:283-293   if (i >= 1) { beat += ...; if (i + 1 < n) { floors[i+1].EntryBeat = beat; ... } }
```

- 最后一块在 `n ≥ 3` 时由 `i = n-2` 那一轮写入（`:288-292` 的 `i + 1 < n` 给它赋值）→ **是累计拍数，不是 0**。
- 只有 `n == 2`（只有一个 `angleData`）时，最后一块就是 `i == 1`，走 `:275-281` 分支被置 0。

即：**模型与引擎在这一点上不一致**（§2.4 分歧 D）。第一轮的 5 张谱判定结果不受影响
（判定不吃 `entryBeat`），但「预检报一条信息：最后一块 entryBeat 为 0」如果要对着模型说话，
模型里读到的是累计值。本文件只指出这一点，不改代码、不选边。
