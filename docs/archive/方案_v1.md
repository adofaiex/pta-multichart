# pta-multichart 方案

多轨道模组。编辑时每条轨道都当成游戏里的那一条主轨来改；存盘和游玩时收成一条原版能玩的单轨，副轨的样子用装饰物画，副轨的点击嵌进主轨。

本文只定方案，不包含模组实现。依据是本机已安装的游戏 **r150**（`Releases.releaseNumber = 150`，Unity 6000.3.25f1，程序集写于 2026-11-12），整包反编译在：

`D:\My WorkStation\adofai-mod\_research\decompiled_r150\Assembly-CSharp\`

`adofai-mod-guide` 正文和 `_research\decompiled\Assembly-CSharp` 是 r148，签名以 r150 这份 dump 为准。adofaiex 上能对上的公开资料也停在 3.4.0 / r150（`7thRhythmSource` 最后一次更新是 “update to test 3.4.0”），没有比本机更新的游戏源码。

## 1. 玩家会看到什么

冰与火之舞只有一条会判点击的轨道。这个模组在编辑器里允许多条轨道，玩的时候仍然只有一条。

- 在主轨的某一砖上创建一条副轨。副轨的第一段出射方向、旋转方向（顺/逆时针）和当时的 BPM 从那块砖抄过来。砖块外观不抄锚点上已经叠上去的变轨、改色，只用关卡轨道设置里的初始样式。
- 切到副轨之后，编辑器里的路径就是这条副轨。方向键铺下一块、事件面板、撤销之外的普通编辑，都走游戏自己的编辑器。
- 游玩时，副轨的砖和在上面走的星球不是真地板。砖用 `AddObject` 且 `objectType` 为 `Floor`；星球用两个 `AddObject`，`objectType` 为 `Planet`，颜色是 `DefaultRed` 和 `DefaultBlue`。沿路径的移动用 `MoveDecorations`。
- 副轨上每一次真正要点的点击，按时间嵌进主轨，变成玩家必须打的一拍。这块插入砖是透明的，不把主轨的形状带偏。
- 没装模组时，关卡仍然能打开、能玩：点击节奏是合并之后的，副轨看起来是装饰。装了模组再进编辑器，会从记号里还原成多轨，而不是让作者去改那条已经合并过的轨。

不注册新的 `LevelEventType`。不写 `requiredMods`。未知事件类型会被游戏整条丢掉，`requiredMods` 非空会直接拒载。

## 2. 编辑器里的数据，和磁盘上的数据

两套数据，随时只让编辑器看见其中一套。

**逻辑谱（编辑中）** 是模组自己的文档：

- 全局设置照旧留在 `LevelData` 的 settings 里（歌曲、初始 BPM、轨道初始样式、相机、背景）。
- 轨道 0 是主轨：`angleData` + 这条轨上的 `levelEvents`。
- 轨道 1 及以后是副轨。每条副轨记录：锚点（主轨的 seqID）、创建时抄下来的出射角、是否逆时针、有效 BPM，以及自己的 `angleData` 和事件列表。
- 作者自己摆的装饰属于「当前正在编辑的那条轨」。生成出来给游玩用的装饰不放进逻辑谱。

**播放谱（磁盘上，以及试玩的那一段时间）** 是游戏原生的单轨文件：合并后的 `angleData`、改写过砖号的事件、副轨的 Floor/Planet 装饰、`MoveDecorations`，外加一条用来还原的 `EditorComment`。

编辑器内存里长期放逻辑谱。只有下面三个时刻换成播放谱，用完立刻换回来：

| 时刻 | 行为 |
|---|---|
| 打开关卡 | 读到记号就把播放谱还原成逻辑谱，编辑器显示主轨 |
| 保存 | 临时编成播放谱写出，内存仍是逻辑谱 |
| 试玩 `Play` | 临时编成播放谱再交给游戏；回到编辑 `SwitchToEditMode` 时还原 |

因此 Ctrl+F 看到的序号，在编辑时就是当前这条逻辑轨的 `seqID`，中间没有插入砖。

## 3. 记号放在哪

用现成事件 `EditorComment`。它只在编辑器里当注释，游玩时不参与判定。

- 写在主轨 0 号砖上，`locked = true`。
- `comment` 以固定前缀开头：`[[PTA-MC:v1]]`，后面换行接 JSON。
- JSON 是整份逻辑谱（每条轨的角度、事件、锚点、抄下来的朝向和 BPM），不是「相对播放谱的补丁」。打开时以它为准整份替换，避免从合并结果反推。
- 编辑过程中把这条注释从事件列表里拿掉，避免评论面板被一大段 JSON 占住。作者自己写的 `EditorComment` 留在各自轨道的事件里，原样保存。
- 前缀不是这个的注释，一律当普通注释。

事件用 `eventTag`，装饰用 `tag`，都是空格分词。模组生成物统一带标签 `pta-mc`，再加轨道标签 `pta-mc-tN`（N 从 1 起）。作者的标签不要用 `pta-mc` 开头。

播放谱里由编译展开出来的事件另加 `pta-mc-unrolled`，避免和原事件一起被重复事件再套一层。

## 4. 创建副轨时抄什么

选中主轨的一块砖，面板上「在此创建副轨」。

从这块锚点砖读三项：

- **出射角**：这块砖的 `floatDirection`。若它自己是中旋（999），沿前一块非 999 的出射角。
- **旋转方向**：这块砖的 `isCCW`。游戏默认是顺时针（`isCCW == false`）。锚点为逆时针时，副轨 0 号砖放一个 `Twirl`。
- **BPM**：`floor.speed * levelData.bpm`，即这块砖当时的有效 BPM。和关卡初始 BPM 不同时，副轨 0 号砖放 `SetSpeed`，`speedType = Bpm`，值为这个绝对 BPM。

不抄的东西：锚点处的 `ColorTrack`、`RecolorTrack`、`ChangeTrack`、贴图、发光。副轨装饰用关卡 `TrackSettings` 的初始样式（`trackStyle`、初始轨道色），这就是「砖块样式为默认」。

副轨初始路径：`angleData` 只有一个角度，等于抄来的出射角。这样有起点砖（seqID 0，不点击）和第一段。之后用编辑器原来的方向键继续铺。

时间原点：副轨的 beat 0 对齐锚点砖的 `entryBeat`（玩家打到锚点的那一拍）。副轨第一次点击是它自己的 1 号砖。

世界位置：副轨 0 号砖叠在锚点砖的世界坐标上。之后每一步用和 `scrLevelMaker.InstantiateFloatFloors` 相同的公式：非 999 时出射角弧度是 `(90 - angleDeg) * π/180`，中旋时出射角等于入射角，位移是 `getVectorFromAngle(exit, tileSize)`。

抄下来的 BPM 是创建当时的绝对值。之后改关卡初始 BPM，不会反向改这条副轨的 `SetSpeed`。

## 5. 编辑时怎么「变成那条主轨」

会话只记住「当前是哪条轨」。切换时：

1. 把编辑器里的 `levelData.angleData` 和 `levelData.levelEvents` 写回当前轨。全局 settings 不动。
2. 把目标轨的角度和事件装进 `levelData`。
3. 调用 `scnEditor.RemakePath()`。
4. 清空 undo/redo。撤销快照是整份 `LevelData`，两条轨混在一个栈里会撤错轨。

装进去之后，方向键、`InsertFloatFloor`、事件面板、`OffsetFloorIDsInEvents` 都在改这条轨自己的数据，不需要再包一层「假地板」。

在副轨上新加的装饰，记在这条副轨上。编译时把它们烤成 `relativeTo = Global` 的世界坐标，不再引用副轨的砖号。主轨上的装饰保持原样，只改砖号。

切轨、试玩、保存期间不要把播放谱写进撤销栈。

编辑器 UI 用挂在编辑器场景上的 IMGUI 面板（在 `scnEditor.Start` 之后创建），不往 `GCS.levelEventsInfo` 里注册事件。面板内容：当前轨名、轨道列表、创建、切换、删除副轨。删除副轨只删逻辑谱，下次保存时播放谱里对应的 `pta-mc-tN` 不再生成。

## 6. 点击时间：为什么不能直接插入 999

r150 里，`angleData[i] == 999` 会把 **i 号砖**标成 `midSpin`，出射角被设成入射角（`scrLevelMaker.InstantiateFloatFloors`）。

离开这块中旋时，行程时间是 0。`CalculateFloorEntryTimes` 里，转过的角度接近 0 或一整圈时：中旋的时间取 0，普通回头弯取 2 拍。`entryBeat` 的推进是 `angleLength / π`，中旋这段加进去的是 0。

落到中旋上之后（`scrPlayer.Hit`）：`midspinInfiniteMargin = true`，并往 `keyTimes` 里补一次按键。`UpdateHoldKeys` 立刻再 `Hit` 一次，下一块用无限判定、不显示判定字。所以 **一次按键打中旋，并自动带过下一块**。净效果是：点击次数不增加，节拍不增加，下一块的独立点击被吃掉。

因此播放谱里如果只插入 999：

- 副轨的那一拍不会变成多出来的一次点击；
- 紧跟在后面的主轨点击会被自动带过；
- 没装模组时节奏是错的。

副轨自己的 999 同样不占拍、不单独要一次点击。编译时不要为「副轨上的中旋砖」再插入一拍。副轨中旋只影响副轨装饰：对应的 Floor 装饰设 `trackType = Midspin`（`FloorDecorationType.Midspin`，游戏会把装饰网格画成中旋）。

## 7. 播放谱怎么插入副轨点击

目标：副轨每一次真正的点击，在主轨时间轴上多一次判定；主星球仍沿原来的弧线走；插入点看不见一块新砖；没装模组也对。

### 7.1 先算两边的点击

对每条轨用同一套节拍数学（与 `scrLevelMaker.CalculateFloorEntryTimes` / `CalculateSingleFloorAngleLength` 一致），输入是该轨的 `angleData`、`Twirl`、`SetSpeed`、`Hold`、`Pause`、`extraBeats`。双星、顺逆时针要算进去。

「真正的点击」= seqID ≥ 1，且上一块不是中旋。起点砖和被中旋自动带过的砖不算。

副轨点击的歌曲时间 = 锚点的 `entryBeat` + 该点击在副轨上的 `entryBeat`。速度不同时，用各自的 BPM 把拍换成歌曲时间再比较，不能直接比拍数。

### 7.2 插在主轨的哪一段

主轨上相邻两次点击 A、B 之间若有副轨点击，就把 A 这段转角按时间切开。每一小段的转角方向与原来相同，长度按拍数比例切，各段 `angleLength` 之和等于原来的 `angleLength`，最后的出口角与没切之前相同。星球因此还在同一条弧上，只是中途多落地一次。

切出来的中间砖就是副轨点击。在这块砖上放 `PositionTrack`：

- `opacity = 0`
- `justThisTile = true`

`justThisTile` 为真时，透明度和位移不往后传递（`scnGame` 里 `output6` 为真则不更新后续砖沿用的 opacity）。这样只有接头是透明的，后面的主轨砖保持原样。

只靠透明度，主轨网格会在接头处断开。同一段再放一个 Floor 装饰，角度用 **没切开之前** 的那一整段，样式用主轨这一段的轨道样式，盖住缺口。这个装饰只负责看起来连续，不参与点击。标签 `pta-mc-mask`。

不要用 999 来当这个接头。999 会把下一次主轨点击吃掉。

### 7.3 砖号

`angleData[i]` 是 i 号砖的出射角，地板块数是 `angleData.Count + 1`。事件上的 `floor` 是 seqID。

编译时维护 `逻辑砖号 → 播放谱砖号`。主轨事件的 `floor` 全部映射过去。`TileRelativeTo` 按 `scnGame.IDFromTile` 的语义改：

- `ThisTile`：偏移改成两端映射后的差。
- `Start`：绝对序号改成映射后的序号。
- `End`：先换成逻辑谱上的绝对序号，再映射，最后写成 `Start`，避免末尾因为插入而错位。

### 7.4 和主轨事件的关系

插入会把后面的主轨点击在歌曲时间上往后推，这是多出来的点击必然的结果。主轨事件跟着新的砖号走，所以仍打在原来那块逻辑砖上，只是那块砖在歌曲里的时刻变晚了。

第一版节拍数学要包含：角度、中旋（0 拍且自动带过下一块）、`Twirl`、`SetSpeed`（Bpm 与 Multiplier）、`Hold`、`Pause`。

第一版若副轨上出现 `FreeRoam`、`MultiPlanet`（行星数不是 2）、`PositionTrack`，创建或切换时直接提示不支持，不参与编译。这三类会改变「一拍多长」或「砖在哪」，和「沿原弧切开」的假设冲突。

## 8. 装饰

样本字段以仓库根目录的 `level.adofai` 里现成的 `AddObject` 为准。游戏侧对应 `scrDecoration` 创建对象装饰、`scrObjectDecoration.SetType`。

每条副轨：

- 每一块逻辑砖一个 Floor 装饰。普通砖 `trackType = Normal`，`trackAngle` 为该砖出射角。副轨上的中旋砖 `trackType = Midspin`。位置 `relativeTo = Global`，坐标用第 4 节的世界坐标。样式用关卡初始轨道设置，不跟主轨中途的改色。
- 两个 Planet 装饰，`planetColorType` 分别是 `DefaultRed`、`DefaultBlue`。`PlanetDecorationColorType` 里这两个值会走游戏默认红蓝预设。装饰物是单个星球精灵，不会自己公转，所以红蓝各一个，用 `MoveDecorations` 让它们绕副轨的轨道点转。
- `MoveDecorations.duration` 的单位是拍，运行时乘 crotchet（`ffxMoveDecorationsPlus.Decode`）。`positionOffset` 的单位是砖长。`tag` 填对应星球的标签。缓动用 `Linear`。
- 公转按副轨的拍取样：每 1/4 拍一个位移，位置是「当前轨道点为圆心、半径为砖尺寸的一半、角度随拍前进」。取样点落在播放谱里时间对齐的那块砖上，这样没装模组也会动。

主轨缺口上的遮盖装饰见 7.2，和副轨装饰分开标签。

作者自己的装饰不要重排相对顺序，只做砖号映射或烤成世界坐标。

## 9. Ctrl+F 和重复事件

这两处都是「数砖」而不是「数拍」。插入接头之后，播放谱的 seqID 比逻辑谱大。

### 9.1 Ctrl+F

r150 编辑器：

- Ctrl+F：`ToggleFloorNumsEditorAction`，开关 `showFloorNums`，再 `RemakePath`。砖上的数字在 `scrFloor.OnBecameVisible` 里写成 `seqID.ToString()`，并且只在 `showFloorNums && !playMode && !isFake` 时出现。
- Ctrl+Shift+F：`ShowCurrentFloorNumberEditorAction`，通知文本用 `selectedFloors[0].seqID`。

编辑时内存是逻辑谱，这两个功能读到的就是当前轨的逻辑序号，不必改数字。

试玩时 `Play` 会把砖号隐藏。若试玩过程中仍触发 Ctrl+Shift+F，会读到播放谱序号。给 `ShowCurrentFloorNumberEditorAction.Execute` 和砖号文本各做一个补丁：会话里若正放着播放谱，把 seqID 译回逻辑序号再显示；接头砖不单独占一个号，显示它前面那块逻辑砖的序号。编辑逻辑谱时补丁是恒等映射。

查找砖（按序号选中）同样走 seqID。编辑态下不拦截。

### 9.2 重复事件

`RepeatEvents` 有两种，r150 `scnGame.ApplyEventsToFloors`：

- `repeatType == Beat`：用 `repetitions` 和 `interval`（拍）。循环不前进砖号，只把角度偏移加上 `interval * n * 180`。砖号插入不会改它的步长。宿主砖的 `floor` 要映射。它的「每 N 拍」是歌曲拍，包含已经插进去的副轨时间。
- `repeatType == Floor`：次数取字段 `floorCount`，步长取 `gapLength`（砖数）。循环是 `for (n = 0; n <= floorCount; n++)`，目标砖是 `seqID + n * gapLength`。`floorCount` 是额外重复次数，加上本砖一共 `floorCount + 1` 次。这就是「重复砖块数量」。

`gapLength` 在播放谱里必须仍是常数。对每个逻辑步检查 `映射(起点 + (k+1)*gap) - 映射(起点 + k*gap)`：

- 全部相等：把 `floor` 改成映射后的起点，`gapLength` 改成这个常数。`floorCount` 不变。
- 不完全相等：按同样的循环，把带有匹配 `eventTag` 的事件复制到每个目标播放砖上，播放谱里去掉这条 `RepeatEvents`（逻辑谱里保留）。复制出来的事件加上 `pta-mc-unrolled`，并且不再带会被这条重复规则再次匹配的 tag。`n` 从 0 计到 `floorCount`，包含起点那一次。

Beat 模式不展开。Floor 模式在步长仍是常数时只改数字，避免把作者的重复事件拆碎。

条件事件（`SetConditionalEvents`）靠 `eventTag` 和重复规则绑在同一砖上。展开时整组一起复制到目标砖，tag 关系保持可匹配，否则条件桶会对不上。

## 10. 要挂的游戏入口（r150）

| 用途 | 方法 |
|---|---|
| 打开后还原 | `scnGame.LoadLevel(string, out LoadResult)` 的后置。仅 `ADOBase.isLevelEditor` 时处理。编辑器在 `scnEditor.OpenLevel` 的协程里调用它（约第 5564 行） |
| 保存前编成播放谱、保存后还原 | `scnEditor.SaveLevel()` |
| 试玩前编成播放谱 | `scnEditor.Play()`，必须在它自己的 `RemakePath` 之前换好数据 |
| 试玩结束还原 | `scnEditor.SwitchToEditMode(bool)` |
| 新关清空会话 | `scnEditor.NewLevel()` |
| 刷新路径 | `scnEditor.RemakePath(bool, bool)` |
| 砖号文字 | `scrFloor.OnBecameVisible` 里对 `editorNumText.letterText.text` 的赋值 |
| 当前砖号通知 | `ShowCurrentFloorNumberEditorAction.Execute` |

保存和试玩的换入/换出放在 finally 里。保存失败也要回到逻辑谱。

不要补 `GCS.levelEventsInfo`。不要改 `LevelEditorProperties`。

模组形态：UMM，程序集名与 `Info.json` 的 Id 都用 `pta-multichart`，入口 `PtaMultichart.Main.Load`。游戏路径用本机安装目录，引用 `Assembly-CSharp.dll` 时 `Private=false`。实现阶段再套 `ADOFAIModTemplate` 的 targets，本方案不生成工程。

## 11. 建议的代码划分（实现时用）

都放在 `project/pta-multichart` 下。

- `Timing/`：不引用 Unity 的节拍计算、弧线切分、砖号映射。用固定小谱做断言（180° = 1 拍、999 不加拍、切分后 angleLength 之和不变、Floor 模式 gap 的两种结果）。
- `Compile/`：逻辑谱 → 播放谱。生成角度、`PositionTrack`、遮盖用 Floor、副轨 Floor/Planet、`MoveDecorations`、注释 JSON。
- `Session/`：当前轨、切换、与 `levelData` 的换入换出。
- `Editor/`：面板，以及第 10 节的 Harmony 补丁。

节拍计算必须能在没有游戏的情况下跑测试。它是插入位置对不对的唯一依据。

## 12. 第一版不做

- 副轨上的自由移动、三颗行星、`PositionTrack`。
- 副轨和主轨的点击落在同一歌曲时间。第一版若时间差小于半个判定窗，拒绝编译并指出是哪两块砖，不叠成双押。
- 让没装模组的编辑器显示逻辑砖号。没装模组时打开的就是播放谱，序号含接头。装模组打开才会还原。
- 公转以外的星球缓动（`planetEase`）。第一版线性取样。
- 把副轨相机、滤镜、判定特效同步到装饰星球上。副轨事件里属于「改这条轨的地板」的（`SetSpeed`、`Twirl`、`Hold`、`Pause`、改色、改打击音）参与编译；相机、滤镜、闪屏留在该轨事件里但第一版不翻译成装饰动画。

## 13. 实现前要用一关小谱核对的事

用一条只有 `[180, 180]`、BPM 100 的主轨，在第一段中间插一个 0.5 拍的副轨点击，编出播放谱后用游戏实际跑一遍，核对四件事：

1. 主星球仍沿原来的直线/弧到达下一块主轨砖，歌曲时间比不插入时晚 0.5 拍。
2. 中间那一下有判定，接头砖看不见，主轨视觉不断开（遮盖装饰在）。
3. Ctrl+F 在编辑副轨和编辑主轨时，数字分别是各轨自己的 0,1,2…，没有接头号。
4. 一条 `repeatType = Floor`、`gapLength = 1` 的重复事件，在「每两块逻辑砖之间都有插入」和「只有某一段有插入」两种谱上，都打在原来的逻辑砖上。第一种应只改 `gapLength`；第二种应展开成 `pta-mc-unrolled`。

这四条通了再铺编辑器面板。节拍或 `PositionTrack` 透明度的传递若和上文不一致，以 r150 里跑出来的 `entryTime` / `opacityVal` 为准改编译规则，不要改回「直接插入 999」。
