## 1. 拍网格（替换 v1 §7.2 / §7.4 / §13-1）— P1

> r150 主轨时长由点击砖块数决定。每向主轨插入一块点击砖，主轨增加恰好 1 拍，角度增量 π，与这块砖和上一砖之间的切弧长度无关。
>
> PositionTrack 只补偿平面位置。它不减少拍，也不能把弧长折回成拍。缩短弧、按弧长比例分配时间、插入后再扣回一拍，都抵消不了这 1 拍。
>
> 插入 N 块点击砖，主轨比插入前多 N 拍。这是引擎模型。方案 v1 的 §7.2、§7.4、§13-1 作废。
>
> 本条只覆盖点击砖。第一轮没有单独测量非点击砖，第二轮不改写它们的拍规则。

**第一轮实测依据**（结果 §3 P1）：`[180,180]`、BPM100 时，1 号砖在 1.800s、终点砖在 2.400s（相差 0.6s = 1 拍）；
在同一位置插一刀成 `[180,270,180]` 后，插入砖落在 2.100s（0.5 拍，符合预期），但终点砖变成 3.000s
（与原来的 2.400s 相比晚 **1 拍**，不是 0.5 拍）。5 张端到端谱在这种模型下判定全是 XPerfect、0 死亡，模型冻结。

### 1.1 结果 §6 第 1 条（原文）

> 1. **先改方案再谈体验**：P1 决定「副轨点击 = 免费插入」不成立。建议明确成拍网格模型：每次副轨点击导出时占主轨 **1 拍**，
>    面板显示「本谱将增加 N 拍」，让作者据此对音乐。要「0.5 拍密度」在当前砖模型无解。

决策表态：**采纳**（决策 §3 第 1 行「拍网格模型 → 采纳 → 第 2 节 P1 替换段落。冻结代码」）。
落点：本章；作者侧的「本谱将增加 N 拍」由第 8 章预检第 1 条承担。

## 2. 位置补偿（新增；P2）— 两条 PositionTrack

> 平面位置与拍分离。插入点击砖带来的位置偏移，用恰好两条已有的 PositionTrack 补偿。不新增 LevelEventType，不把补偿写进 requiredMods。
>
> 两条 PositionTrack 的分工、参考砖和偏移量，以第一轮实现为准，从代码原样抄入本节。第二轮不改这条公式。补偿之后拍数仍遵守拍网格：插了 N 块点击砖就多 N 拍。

### 2.1 两条 PositionTrack 的分工（从第一轮代码摘录）

来源：`实现摘录_v1.md` §1；代码 `src/Core/Compile/ChartCompiler.cs` → `EmitPositionCorrections`（`:191-220`）。

| 项 | 第 1 条（PT-1） | 第 2 条（PT-2） |
| --- | --- | --- |
| 挂在哪块砖 | **插入砖自己**（`insertedFlags[i] == true`），每条插入砖最多 1 条 | **需要补偿、且不是插入砖**的播放砖；现有输入上就是「被切逻辑砖 `k` 的后继砖」＝`FloorMap.ToPlayable(k+1)`，每条砖最多 1 条 |
| 参考砖 | 该插入砖自己：`ideal = IdealArcPoint(arcStart, arcEnd, sweep, isCCW, cumulative)`，`arcStart/arcEnd` 取**逻辑**主轨时间线的 `Positions[k]/[k+1]` | 同一块砖（代码字面）／意图是逻辑 `k+1` 的播放砖；两种说法在现有所有输入上数值等价（摘录 §2.2） |
| `justThisTile` | `true` | 不写这个 key（引擎按 `false` 处理 → 补偿向后传递） |
| 是否带 `opacity` | 带，`0.0`，**与位置补偿合成同一条事件** | 不带 |
| `positionOffset`（单位：砖长） | **见 §2.2**：`need` 还是 `need − carry`，两种读法 | **同 §2.2** |
| 写入后 `carry` | 不变 | 更新为 `need` |
| 作用 | 把插入砖摆回原弧上按比例的位置，并让它不可见 | 把后续所有砖拉回原位 |

其中 `need = idealPos[i] − natural[i]`；`natural` = 链式位置 `pos[i+1] = pos[i] + v(exit_i)`（`NaturalPositions`）。
单位是砖长（引擎在 `scnGame.ApplyCoreEventsToFloors` 里再乘 `tileSize`）。
引擎侧的累加规则：本砖位置 = 起点 + （上砖传下来的累计 + 本砖所有 `positionOffset`），
只有本砖出现**非** `justThisTile` 的 `PositionTrack` 时，这个累计值才传给后续砖。

### 2.2 ★ 偏移量的基准有两种读法（P2 本节不冻结）

代码里同时存在两种都能自圆其说的读法，T2 按决策的停止条件**没有选边**：

- **读法 A1（绝对）**：`positionOffset = ideal − natural`。
  依据：`ChartCompiler.cs:199` 先算 `need`；`notes-compile.md:21/27` 就是这么写的。
  单处切分时，它与真正写进事件的值完全一致。
- **读法 A2（相对 carry 的增量）**：`positionOffset = need − carry`，`carry` = 前面 PT-2 传下来的累计偏移，
  只在非插入砖的补偿事件上更新（`ChartCompiler.cs:200/:208/:216/:218` 写进 `Data` 的正是它）。

两者只在**同一张谱出现第二处及以后切分**时不同（第一处 `carry == 0`）。实测例（主轨 `[180,180,180]` +
副轨 `[0,90,90]`、锚 1，探针实跑）：第二处切分的 PT-1 写 `(-0.5, 0.5)`，而 `ideal − natural` 是 `(-0.5, 1.5)`；
PT-2 写 `(0, 1)`，而 `ideal − natural` 是 `(0, 2)`。

后果：只写 A1 会让照抄实现的人在多处切分时把误差累加成两倍、位置再错开一块；写 A2 则必须同时定义
`carry` 的更新时机（只在非插入砖的补偿事件上更新，插入砖不更新）。

**处置**：本节两种读法都保留，**P2 不冻结**（决策 §5 T2 停止条件）。等拍板选一种后，把另一条删掉，
本节即可冻结；其余章节不受影响，可以继续（拍网格、装饰、0/1 号砖、tag、预检都不依赖这个基准）。

### 3.2 第一轮代码里的段定义（摘录）

来源：`实现摘录_v1.md` §3；代码 `ChartCompiler.AddPlanetMoves`（`:698-723`）、`AddMove`（`:733-745`）、
`DecorationBuilder.MoveDecorations`（`DecorationBuilder.cs:146-154`）。

| 段 | 起点（= `MoveDecorations` 挂的播放砖） | 终点（`positionOffset` 的目标） | `duration` |
| --- | --- | --- | --- |
| 第 1 段 | **锚点砖**（`map.ToPlayable(Anchor)`） | 第一次插入点击的副轨砖 | `first.Time − AnchorTime` |
| 第 i 段（i ≥ 1） | 第 i 次点击的**插入砖** | 下一次点击的副轨砖 | `b.Time − a.Time` |

- 折线节点 = **`[锚点砖] + [每次插入点击对应的副轨砖]`**；最后一击之后没有段
  （循环 `i + 1 < Clicks.Count`）。所以严格说「以副轨相邻点击砖为段」覆盖的是第 2 段起，
  第 1 段的起点是锚点砖（锚点本身在主轨上已经是一次点击，见第 4 章）。
- `duration`（单位＝播放谱的拍）= 段两端的**歌曲时间差（秒）× 主轨 BPM / 60**。
- `positionOffset` = 目标点 − `world[1]`（星球装饰的 `startPos`，即副轨 1 号砖＝锚点砖）。
  引擎侧是 `startPos + targetPos`，所以这里写的是**相对装饰自身 `startPos` 的绝对量**，
  不是「相对上一段终点」。
- 红蓝各一条，`duration`/`positionOffset` 相同，只有 `tag` 不同；`ease = Linear`；目标点或时长非正时该段不写事件。

## 4. 副轨 0/1 号砖（替换 v1 §4、§7.1 的时间原点）— P4

> 时间原点是锚点，不是副轨 0 号砖。
>
> - 副轨 seq1 不插入主轨。
> - 1 号砖对齐锚点。
> - 0 号砖是幽灵起点：只给副轨内部提供进入几何，不进入主轨砖列，不占拍，不参与判定。
>
> 原 §4 与原 §7.1 里与本条不一致的时间原点表述，以本条为准。

**说明（非决策原文）**：v1 §4 里「抄出射角 / 抄旋转方向 / 抄有效 BPM」「副轨初始 `angleData` 只有一个角度」
「不抄 ColorTrack 等样式」这些仍然有效；被替换的是「副轨 0 号砖叠在锚点砖的世界坐标上」与
「时间原点对齐锚点、第一次点击是 1 号砖」这两句的组合口径——按本章，**锚点同时是 1 号砖的位置和时间原点**，
0 号砖在锚点之前一块、只提供进入几何。v1 §7.1 里「真正的点击 = seqID ≥ 1 且上一块不是中旋」保持，
但副轨侧不再把 seq1 当成要插入主轨的那一拍（seq1 = 打到锚点的那一次按键，主轨上已经有这一拍）。

### 4.1 结果 §6 第 4 条（原文）

> 4. **§4 口径二选一**：建议采纳「副轨 1 号砖 = 锚点（坐标与时间都对齐），0 号砖是幽灵起点不绘制」。

决策表态：**采纳**（决策 §3 第 4 行「副轨 0/1 号砖口径 → 采纳 → 第 2 节 P4」）。
落点：本章。

## 6. 最后一块 entryBeat（P6）与判定窗（P7）

## 附录 B：冻结与不变项

- **拍模型冻结**：一块插入的点击砖 = 主轨 1 拍（角度 π）。不改时长、不改弧长折算、不做「插入后扣回一拍」。

  拍板后删掉另一种读法即可冻结；T3 不得改公式。
- **装饰冻结**：按副轨相邻点击砖分段、段内线性折线；不提高取样密度，不改曲线。
- **0/1 号砖冻结**：seq1 不插入；1 号砖对齐锚点；0 号砖幽灵（不占拍、不判定、不绘制）。
- **entryBeat 冻结**：最后一块恒为 0 记为现状，不作缺陷修。
- **判定窗**：沿用引擎默认，不写入、不配置、不在预检展示。
- **接口不变**：不注册新的 `LevelEventType`；不写 `requiredMods`；模组 tag 不加前缀。
- **测试基线**：原 TimingTests 47 条、原 CompileTests 118 条的期望值不变；允许为预检 6 条新增断言。
- **本轮唯一行为变化**：第 5 章的 tag 冲突退让。
- **工具约束**：禁止 computer use；需要游戏时只用隐藏桌面 + `pta-bridge` HTTP。
