# 结果 v1：pta-multichart 实现与测试报告

> 对应方案：`方案_v1.md`（下称「方案」）。环境：本机 r150 / 3.4.0 / Unity 6000.3.25f1，
> 游戏目录 `I:\Program Files (x86)\Steam\steamapps\common\A Dance of Fire and Ice`。
> 全程**没有使用 computer use**：启动游戏走隐藏桌面（`tools/game-run.ps1`，不抢焦点、静音），
> 所有控制/读取通过自写的进程内 HTTP 桥 `pta-bridge`（§2.3）。

## 0. 一句话结论

模组按方案实现，主流程（打开还原 → 编辑多轨 → 保存编播放谱 → 试玩 → 回到逻辑谱）全部跑通；
单元测试 **47 + 118** 条断言、端到端 **5 张谱** 全部通过（每张谱的所有判定都是 XPerfect、0 死亡）。

**但方案里有 3 条核心假设在 r150 实测不成立**，其中一条是硬伤：

> **「副轨的一次点击嵌进主轨、主轨只按副轨那一拍顺延」在 r150 的砖模型里做不到。每插入一块砖，主轨必然多出恰好 1 拍（π），而且插入砖会让其后所有砖位移一整块。**
> 位置可以用 `PositionTrack` 补偿回来（已实现），节拍补不回来。

证据是游戏内读到的 `scrFloor.entryTime`（§3 P1）。其余问题（§8 的 1/4 拍取样、§4 与 §7.1 的时间原点矛盾、
§9.2 的 tag 冲突）都已按「能做到的最好形态」实现并记录。

## 2. 做了什么

### 2.1 数据模型（方案 §2/§3）

- **逻辑谱**：`LogicalChart { tracks[] }`，每轨 `Track { id, anchor, exitAngle, ccw, bpm, angleData[], actions[], decorations[] }`。
  轨道 0 = 主轨；副轨记录锚点砖号、抄下来的出射角/方向/有效 BPM。全局 settings 不进逻辑谱。
- **记号**：主轨 0 号砖一条 `EditorComment`（`locked=true`，`comment = "[[PTA-MC:v1]]\n" + JSON`）。打开时整份替换，
  并从事件列表移除；保存/试玩时重新写入。实测多次保存/重开后文件里始终只有 1 条记号（不叠加）。
- 生成物 tag：`pta-mc`、`pta-mc-tN`、`pta-mc-tN-red|blue`、`pta-mc-mask`、`pta-mc-unrolled`。

### 2.2 会话与换入换出（方案 §5/§10）

| 用途 | 目标 | 做法 |
|---|---|---|
| 打开后还原 | `scnGame.LoadLevel(string,out LoadResult)` postfix | 有记号 → 解析 → 主轨装回 `levelData`、移除记号；无记号 → 建单轨会话；同路径 2s 内重复调用被去重 |
| 保存前编译 / 保存后还原 | `scnEditor.SaveLevel()` prefix + **finalizer** | prefix 换入播放谱（`levelData.Encode()` 写出的就是播放谱），finalizer 一定换回；若保存发生在试玩中则不接管 |
| 试玩前编译 | `scnEditor.Play()` prefix + postfix | 编译失败 → `return false` 取消试玩并弹通知；postfix 刷砖号文字 |
| 试玩结束还原 | `scnEditor.SwitchToEditMode(bool)` prefix 记状态 / postfix 换回 + `RemakePath()` | **不能**在 prefix 换数据（见 §4.2） |
| 新关清空 | `scnEditor.NewLevel()` postfix | 重建单轨会话 |
| 检查点砖号 | `scnGame.Play(int,bool)` prefix | 逻辑砖号 → 播放砖号并 clamp |
| 砖号文字 | `scrFloor.OnBecameVisible()` postfix + `RefreshFloorNumbers()` | 试玩态译回逻辑号；退出试玩/切轨后主动刷新（r150 复用旧砖不会重写文字） |
| 当前砖号通知 | `ShowCurrentFloorNumberEditorAction.Execute` prefix | 直接给逻辑号并跳过原实现 |
| 面板 | `scnEditor.Start` postfix | IMGUI 面板：当前轨、轨道列表、创建/切换/删除副轨、编译预览 |

切轨：写回当前轨 → 装目标轨 → `RemakePath()` → 清 undo/redo → 刷新砖号。
创建副轨（§4）：从锚点砖读 `floatDirection`（999 则沿前一块非 999）、`isCCW`、`speed*bpm`；
副轨 `angleData=[exitAngle]`，逆时针加 `Twirl`，BPM 不同加 `SetSpeed(Bpm)`。
副轨作者装饰按 §5 烤成 `relativeTo=Global`。

### 2.3 测试桥 `pta-bridge`

进程内 `HttpListener`（127.0.0.1:59731，ACL 失败自动退回 TcpListener），Unity 访问全部经主线程队列。19 个 cmd：
`ping/state/floors/openlevel/openeditor/save/play/exitedit/setauto/hits/resethits/setfloornums/selectfloor/invoke/screenshot/log/quit/gotolevelselect/help`。

- `floors` 给每块砖的 `entryTime/entryBeat/speed/isCCW/midSpin/angleLength/opacityVal/holdLength/position/editorNumText`——
  本报告所有「游戏实际怎么走」的数据都来自它（方案 §13 的验收就是靠它做的）。
- `hits` 读 `scrMistakesManager.marginTrackers[0].hitMargins`——数「到底判了几次点击」。
- `screenshot` 相机渲染 PNG（游戏内读取）；截图需要 IMGUI 时用 `invoke UnityEngine.ScreenCapture.CaptureScreenshot`。
- `invoke` 反射口，配合 `PtaMultichart.Api` 可以无 UI 切轨/建副轨/编译探针。

### 2.4 编译（方案 §7/§8/§9）

1. 与 `scrLevelMaker` 一致的节拍数学（`Timing/`）。
2. 主轨相邻两次点击之间的每个副轨点击，按时间找宿主砖、按时间比例切砖（最后一段出口角精确等于原角），
   插入砖 `PositionTrack{opacity=0, justThisTile=true, positionOffset=…}`，同段加 `AddObject/Floor` 遮盖装饰。
3. **位置补偿**（方案没写，实现补丁）：插入砖拉回原弧上的理想点（`justThisTile`），紧随其后的原主轨砖加一条
   传播型 `PositionTrack` 把后续所有砖拉回原位。实测 t1：`(0,0) → (-1.5,0) → (-2.25,-0.75) → (-3,0)`，
   第 4 块与不插入时完全一致，插入砖在圆心 `(-2.25,0)`、半径 0.75 的原弧上（`opacityVal=0`）。
4. 砖号映射 + `TileRelativeTo`（`ThisTile` 差 / `Start` 绝对 / `End`→`Start`）。
5. `RepeatEvents(Floor)`：步长恒定 → 只改 `floor`+`gapLength`；不恒定 → 复制带匹配 `eventTag` 的事件
   （加 `pta-mc-unrolled`、摘掉匹配 tag）并删掉规则。`Beat` 模式只映射 `floor`。
6. 副轨装饰：每段弧一个 Floor 装饰（中旋 → `Midspin`）、红蓝两颗 Planet、`MoveDecorations` 让星球沿轨道移动；
   全部 `relativeTo=Global`。【副轨 1 号砖 = 锚点砖坐标，0 号砖是幽灵起点不绘制】

## 3. 方案逻辑问题（实测发现，**不是实现 bug**）

### P1 ★★★ 插入一次点击，主轨必然多 1 拍（§7.2/§7.4/§13-1 不成立）

r150 每块砖的入口方向 = `上一块 exit + π`（`scrLevelMaker.InstantiateFloatFloors` 第 543 行），
每块砖的时长 = `mod((exit-entry)*dir, 2π)/π` 拍（`scrMisc.GetTimeBetweenAngles`）。
因此一串砖的总旋转 = 首末方向差 + 砖数×π：**每多一块砖，整条轨就多 π（1 拍），与这块砖切多长无关**。
数学上 n 块砖的总和只能落在 `S ± π + 2πk`，不可能等于原来的 S——「切弧后 angleLength 之和不变」在 r150 没有解。

**游戏内实测**（BPM100，读 `scrFloor.entryTime`）：

| 谱面 | floor1 | floor2 | floor3 | 每段 |
|---|---|---|---|---|
| `[180,180]`（原谱） | 1.800s | 2.400s | — | 0.6s = 1 拍 |
| `[180,270,180]`（在 1 号砖 0.5 拍处插一刀） | 1.800s | **2.100s** | **3.000s** | 0.3s（0.5 拍）+ 0.9s（1.5 拍）= **2 拍** |

- 插入的那一拍**确实落在 0.5 拍**（方案 §7.2 的时间点是对的）；
- 但下一次主轨点击被推到 **+1 拍**，不是 §13-1 期望的 +0.5 拍；
- §7.4「会把后面的主轨点击往后推」方向对，但量是**每插一块 +1 拍**，不是「副轨那一拍的间隙」。

**影响**：副轨点击越密，导出谱后面的主轨点击相对音乐偏移越多（每个 +1 拍）。这是砖模型的硬限制。

### P2 ★★★ 插入砖会把其后所有砖整体位移一整块（§7.2「还在同一条弧上」不成立）

链式 `pos[i+1] = pos[i] + vec(exit_i)`（`tileSize=1.5`），插入一块砖就多走一步且后续不回头。
实测（未补偿版本）t1：`(0,0) → (-1.5,0) → (-1.5,-1.5) → (-3,-1.5)`，从第 2 块起整条主轨被拽下去 1.5 格。

**本模组的处理**：两条 `PositionTrack` 补偿（见 §2.4-3）。补偿后实测 `(0,0) → (-1.5,0) → (-2.25,-0.75) → (-3,0)`：
除接头处局部变成「两段半圆」外，关卡形状与原来一致。**这条方案里必须补写**，否则实现者会踩。

### P3 ★★ §8 的「每 1/4 拍一个位移」挂不到砖上

`MoveDecorations` 只能挂在砖上、按砖的拍触发；播放谱里没有 1/4 拍粒度的砖（有的话就等于又插了一块砖 → P1）。
现状：每个「副轨点击区间」一条 `MoveDecorations`（红蓝各一），线性插到下一次点击的轨道点——星球走**折线**，不是圆弧。
想要圆弧只能加挂载点，而每个挂载点都是一块砖 → 又回到 +1 拍。**§8 与 §7 在这个模型下互斥。**

### P4 ★★ §4 与 §7.1 的时间原点/世界坐标互相矛盾

§4 要求「副轨 0 号砖叠在锚点世界坐标上」「第一次点击是 1 号砖」「beat 0 对齐锚点 entryBeat」；
§7.1 又把 seq1 算成一次点击。合起来意味着副轨 1 号砖**既在锚点位置、又要和锚点同一时刻被点**——
那它不是新点击，而是「打到锚点」的同一按键；照 §7.1 全插进去会和主轨锚点点击撞在同一时刻（被 §12 拒绝）。

**本模组的处理**：副轨 seq1 不插入（= 锚点那次按键）；装饰以「1 号砖 = 锚点坐标」为准，
0 号砖是幽灵起点（不画、不计时）。

### P5 ★ §9.2 的展开与 `SetConditionalEvents` 的 tag 规则冲突

方案既要求「展开副本去掉会被再次匹配的 tag」，又要求「条件事件整组复制、tag 保持可匹配」。
同一 tag 同时被重复规则和条件桶引用时两条不能同时满足。当前按方案字面实现（摘 tag + `pta-mc-unrolled`），
这种情况下条件桶会失配——需要方案层面定优先级。

### P6 ★ 游戏怪癖：最后一块砖的 `entryBeat` 恒为 0

`CalculateFloorEntryTimes` 的 entryBeat 循环只跑到 `Count-2`，最后一块砖的 `entryBeat` 保持默认 0
（`entryTime` 正常）。外部工具用 beat 比较最后一块砖会被坑；模组内部用自己的 `TimingBuilder`，不受影响。

### P7 方案 §12 的「半个判定窗」没有数值

判定窗随 BPM/难度变化。当前取 `CompileSettings.MinClickGapSeconds = 0.05s`（可调），
冲突时抛 `OverlappingClick` 并指出主/副两块砖号。

### P8 §6 的 999 分析正确，但它同时否证了「加点击不加时间」

999 不占拍、会吃掉下一块的点击；正因如此它也不能承载「多出来的一次点击」。
**在 r150 里「多一次独立点击」⇔「多一块砖」⇔「多 1 拍」。** 这是 P1 的另一面。

## 4. 我自己代码的问题（发现 → 修好）

1. **Harmony 补丁被应用两次**（`Main.Load` 里 PatchAll + UMM 启动回调 `OnToggle(true)`），一次 `LoadLevel` 触发两次会话重建，
   副轨会话被第二次「无记号 → 新建单轨会话」清空。→ `_patched` 幂等标记 + 逐 patch class 应用（单个失败不影响其它）。
2. **`SwitchToEditMode` 在 Prefix 里换回逻辑谱导致索引越界**：方法体用「播放谱的 floors」索引 `levelData`，提前换数据 →
   `ArgumentOutOfRangeException`。→ Prefix 只记状态、Postfix 换数据 + `RemakePath()`，并加 finalizer 记录异常。
3. **同一次打开关卡 `LoadLevel` 被调用两次**（`OpenLevelCo` 路径）。→ `PatchLoadGuard`：同路径 2 秒内视为重复。
4. `EventFactory` 局部变量名与 switch case 内变量冲突（CS0136）；`ChartEvent.Pair(int,string)` 缺重载。→ 修。
5. PowerShell 客户端 `function C($cmd,$args)` 撞上自动变量 `$args`，参数永远为空。→ 改用 `$A` 并封装 `tools/pta.ps1`。
6. **退出试玩后砖号文字是上一套（甚至播放谱的）号码**：r150 只在 `OnBecameVisible` 写文字，`RemakePath` 复用旧砖时不重写。
   → 加 `RefreshFloorNumbers()`，切轨/退出试玩/试玩开始时主动刷。
7. 测试谱 fixture 用了 `SetHitsound.gameSound="Kick"`（该字段是另一个枚举，没有 Kick）→ 关卡拒载（`Requested value 'Kick' was not found`）。
   → 改用 `hitsound` 字段。这是测试数据的坑，也说明「作者的坏事件会被原样带进播放谱」，值得在预检里报。

## 6. 想法 / 建议

1. **先改方案再谈体验**：P1 决定「副轨点击 = 免费插入」不成立。建议明确成拍网格模型：每次副轨点击导出时占主轨 **1 拍**，
   面板显示「本谱将增加 N 拍」，让作者据此对音乐。要「0.5 拍密度」在当前砖模型无解。
